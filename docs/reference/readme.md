# 設計と変換の規則

[README](../../README.md) / 検証記録

## 全体の流れ

1. 文書を comrak と同じ規則で読み、パイプ表と HTML の表を見つける（`mdtable/blocks.py`・`document.py`）
2. 表ごとに格子のモデル（セルの位置・結合・見出し・配置・Excel に書く Markdown）を作り、ブックに書く（`workbook.py`）
3. 取り込みでは、ブックのモデルを元の表のモデルと比べ、違う表だけを書き戻す（`sync.py`）
4. 書き戻した文書を読み直し、表の場所・前後の解釈・もう一度書き戻したときの結果が変わらないことを確かめてから書く

## comrak に合わせた理由

GitLab は Markdown を comrak で解析します。表の検出や「HTML ブロックの中のどこが Markdown か」を自前で決めると、GitLab と違う所を表として読んだり、書き戻した表が GitLab で崩れたりします。そこで comrak の `src/parser/mod.rs`・`table.rs`・`scanners.re` の規則をそのまま Python に移しました。手元の文書 217 本で、葉のブロックの種類・行・祖先と表の行が comrak の構文木と一致することを確かめています（検証記録）。

comrak の主な規則:

- 表は段落の最後の行と区切り行で始まる（段落を中断できる）。`---` だけの行は setext の見出しが先。同じ段落で一度失敗したら、その段落ではもう表にしない
- 表の行は、空行・コンテナの終わり・別のブロックの始まりまで続く。`|` の無い行も行になる。遅延行では続かない
- セルの区切りの `|` は、直前に `\` が 1 つでもあれば区切りにならない（`\\|` も区切らない）。セルの中身からは、奇数個の `\` の直後の `|` について `\` を 1 つ除く。書き戻しでは、`|` の前の `\` が偶数個（0 を含む）なら 1 つ足す。コードスパンの中の奇数個の `\` + `|` はパイプ表では書けないので、HTML の表にする
- 説明リストの説明の中身は、`:` の位置 + `:` と後ろの空白の幅（comrak の `marker_offset + padding`）の列から始まる

## ブックの形

- 「目次」シート、表ごとのシート（表は A1 から）、隠しシート `_mdtable`（veryHidden）
- 書き出す表が 1 つなら、開いたときのシートはその表のシートにする。2 つ以上なら「目次」にする
- セルは文字列の書式（`@`）で、値は代入した後に `data_type = "s"` にする。`=` で始まる文字や `#N/A` を数式・エラー値にしないため
- 列のスタイルにも `@` を付け、表の右にも数列分を足す。後から入力したセルも文字列になる。列のセルの配置がそろっていれば、列のスタイルにもその配置を付ける（表の下の行に入力したセルも同じ配置になり、パイプ表の列の配置と混ざらない）
- 結合で隠れるセルにも、左上のセルと同じ書式を付ける。結合を解いて入力しても文字列のまま（openpyxl は結合すると隠れるセルの書式を捨てるので、結合してから書式を付ける）
- 表全体の範囲に名前の定義 `mdtable_番号` を付ける。シート名を変えると Excel が参照を直すので、どのシートがどの表かを追える。目次のリンクもこの名前を指す
- `_mdtable` には、Markdown の絶対パスと相対パス、表ごとの種類・行範囲・元の表の本文の sha256・シートを読み直した形の指紋を書く。HTML の表でセルの無い位置は、指紋では空のセルにする
- 同じ本文の表の中での順番（`occurrence`、0 起点）と、書き出したときの文書にある同じ本文の表の数（`same`）も書く。数えるのは、表の検出で対象外にならなかった表だけ。形式の版は 1 で、`same` の列が無いブックも読める
- `_xHHHH_` の形の文字は `_x005F_xHHHH_` にして書く（Excel が文字に戻してしまうため）。読むときは逆にし、`_x000D_` + 改行は改行にする
- 結合を含む行は Excel が高さを自動で合わせないので、内容から見積もる
- フォントは、書き出す PC に HackGen Console NF（日本語の等幅で、`\` が `¥` に見えない）が入っていればそれ、無ければどの Windows にもある BIZ UDゴシック。Windows はフォントの登録（`HKLM` と `HKCU` の `SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`）、ほかの OS は `fc-list` で調べる。環境変数 `MDTABLE_FONT` があれば、それを使う

## セルの文字（Excel 側の Markdown）

- セル内の改行は表示上の改行（GitLab では `<br>`）、空行は段落の区切りとして扱う。Excel で Alt+Enter した改行がそのまま改行に見えるようにするため
- それ以外は GLFM の Markdown のまま（リスト・説明リスト・コードブロック・強調・リンク・直書きの HTML）

### パイプ表のセル

- Excel へ: `<br>`（`<br/>`・`<BR >` も）を改行に、`<ul>`・`<ol start>`・`<dl>` の決まった形をリストと説明リストにする。それ以外のタグや文字はそのまま。行頭がブロックの記法になる文字（空白が続く `-`・`1.`・`:`、`>`・`#` など）はエスケープする（パイプ表のセルの中では文字として表示されているため）
- Markdown へ: 段落の中の改行は `<br>`、段落の区切りは `<br><br>`、リストは `<ul><li>`、説明リストは `<dl>`。インラインの Markdown はそのまま。行頭のエスケープはパイプ表の中では要らないので外す
- コードブロック・タスク・見出し・引用・字下げのコード・結合はパイプ表では書けないので、その表を HTML の表にする。`import`・`edit` に `--keep-kind` を付けると、HTML の表に変えずに理由を出し、文書全体の書き戻しを止める。表の次の行が同じコンテナの空でない行なら、`</table>` の後に空行を足す（HTML ブロックが次の行まで続かないように）

### HTML の表のセル

- GitLab の文書は、セルにリストやタスクを書くときは `<td>` の中に空行で区切った Markdown を書くよう勧めています。HTML ブロックの中では、同じ行の `**` などは処理されず、空行で区切った行だけが Markdown になるためです。そこで、書式のあるセルは `<td>`・空行・Markdown・空行・`</td>` で書き戻します
- 書式の無いセル（Markdown の記号もブロックの記法も無い）は `<td>文字</td>` の 1 行にし、改行は `<br>` にします
- Markdown の部分では、段落の中で次の行に続く行の末尾に `<br>` を足します（Markdown では改行が空白になるため）。読むときは逆に、`<br>` などの改行マークの付いた改行を改行に、マークの無い改行を空白にします
- リストとフェンスの前に空行を入れ、markdownlint の自動修正（MD031・MD032）が入らない形にします
- 閉じていないフェンスは閉じて警告します。閉じていない `<pre>` やコメント、コードの外の `<td>` などの表の構造のタグがあれば、書き戻さずに止めます
- `- [注]` のような 1 文字のタスク（GitLab は任意の 1 文字をタスクにする）は、`- \[注]` で書き戻します。`- [ ]`・`- [x]` はタスクのまま

### HTML から Excel へ

- `<p>` は段落、`<br>` は改行、`<ul>`・`<ol start>`・`<li>` はリスト（入れ子は親の文字の位置まで字下げ、隣り合う同じ種類のリストは記号を変える）、`<input type="checkbox">` はタスク、`<dl>` は説明リスト、`<pre>` はフェンス（`class="language-x"` や `lang` を言語名に）、`<code>` はコードスパン、`<strong>`・`<em>`・`<del>` は `**`・`*`・`~~`、`<a>` はリンク、`<img>` は画像、`<blockquote>` は引用、`<h1>` などは見出し
- `**` などが CommonMark の規則で強調として成り立たない位置（「」などの約物に接して閉じる、隣が `*` など）では、`<strong>…</strong>` のまま残します
- 属性付きの `<a>` や、知らない要素（`<kbd>`・入れ子の `<table>` など）は HTML のまま残します
- HTML の文字は空白をまとめ、実体参照を戻してから、Markdown で意味を持つ文字だけをエスケープします（`` ` ``・`*`・`[`・境界の `_`・組になる `~` と `$`・`<` + 英字・実体参照に見える `&`、行頭の記法）。`#123` や `@user` などの GitLab の参照の記号はエスケープしません

## 表の種類を変える

- `convert <文書> --table <番号|L行|見出し> --to html|pipe` は、Excel を通さずに表の種類だけを変えます。`--table` と `--to` は必須で、表は `export` と同じ選び方で複数指定できます。選んだ表が既に指定の種類なら、その表は変えません
- `--dry-run` は書き戻さずに差分を出します。1 表でも対象外・変換できない・読み直しで問題がある場合は、文書全体を書き戻しません
- パイプ表から HTML の表へは、取り込みで使う生成処理と同じ形で書きます。表の次の行が同じコンテナの空でない行なら空行を足し、詰めたリストの中なら項目の間隔が広がる警告を出します
- HTML の表からパイプ表へは、行頭と行末に `|`、セルの前後に空白を入れます。区切り行は `| --- | :---: |` の形にし、セル内の改行は `<br>`、リストは `<ul><li>` など、`|` はエスケープして書きます。最初の行と続きの行の接頭辞を保ち、次の行が同じコンテナの空でない行なら空行を足します
- パイプ表にできるのは、結合とセルの無い位置が無く、1 行目がすべて見出しセルで、2 行目以降に見出しセルが無い表です。各列の配置はすべての行で一致する必要があり、`justify` は扱いません
- `<caption>`・`<colgroup>`・`<col>`・`<tfoot>`、2 行以上の `<thead>`（パイプ表の見出しは 1 行だけ）、表の構造の間のコメントなど、表の前後の同じ行の文字がある表は、パイプ表にしません。`<table>`・区画・行に属性がある表も変えません（配置として読むのはセルの属性だけで、`<table>` や `<tr>` の `align` はパイプ表にすると消えるため）。セルの属性は、`align`・`text-align` だけの `style`・`rowspan="1"`・`colspan="1"` だけを扱います
- セルの中に入れ子の表がある表も変えません。コードの中の `|` は `\|` と書き、読み直すと同じ文字になります
- コードブロック・タスク・見出し・引用など、セルの内容がパイプ表のセルに書けない場合も変えません。位置が分かる理由には、表の中の行と列を付けます
- 書き戻す前に文書を読み直し、表の外の葉のブロックの種類・祖先・位置が変わらず、置き換えた範囲に指定の種類の表が 1 つあり、対象外でなく、表の場所も同じであることを確かめます
- さらに、元のモデルと読み直したモデルの行数・列数、セルごとの位置・結合・見出し・配置・文字を比べ、1 つでも違えば書き戻しません。種類を変える場合には、取り込みの「HTML の表の形の比較」と「再度の書き戻しで同じ行になること」の代わりに、この内容の比較を使います。取り込みの自動変換の検証は同じです
- 違いがあったときは、どのセルがどう変わるかを 2 個まで出します。HTML の表は、読み直すとセルの文字の連続した空白が 1 つにまとまるので、連続した空白のあるパイプ表は HTML の表に変えません（描画は同じでも、もう一度 Excel に書き出したときの文字が変わるため）
- BOM と改行コードは取り込みと同じ方法で保ち、選ばない表と表の外の行は書き換えません

## 変えていないものを変えない仕組み

- 取り込みでは、先にシートの指紋を書き出したときの指紋と比べます。同じなら「変更なし」とし、文書側を編集していても `--force` を付けても、その表は変えません。パイプ表の見出しは、比較するときに 1 行目にそろえます
- 同じ番号の表の本文が変わっていても、シートの内容を書き戻した結果が今の行と同じなら「適用済み」です。この判定を、元の本文の sha256 で表を探す前に行います。ただし、同じ番号の表がブックのほかの表の元の本文のままなら、文書の中で表を入れ替えたとみて、この判定を飛ばします
- 元の表の本文（コンテナの接頭辞を除いた行）の sha256 で、今の文書の表を探します。同じ本文の表の数が書き出したときと同じなら、その中の順番で対応させます。`same` の列が無いブックは、数を比べずに順番で対応させます。表の外を編集しても衝突になりません
- 対応する表が決まらなければ、同じ番号の表で「適用済み」かを確かめ、違えば衝突です。`--force` を付けると同じ番号の表を上書きします。同じ本文の表の数が違うときは、書き出したときと今の数を衝突の理由に出します
- 「適用済み」を書き戻した行で比べるのは、列の配置を多いほうにそろえたり、セルの文字を収束する形（`- a⏎b` → `- a⏎  b`）に直したりするためです
- パイプ表: 変わっていない行は元の行のまま、変わった行でも変わっていないセルは元のセルの文字のまま書きます（行の対応は difflib）
- HTML の表: 格子の形（各セルの位置と結合範囲）が同じなら、元の文字の上で、変えたセルの中身と、見出し・配置を変えたセルのタグだけを書き換えます。形が変わったら表を作り直しますが、変わっていない行は元の行の文字、変わっていないセルは元の中身のままです
- 置き換える範囲でも、変えていない行の改行コードは元のまま保ちます。変えた行と足した行は、範囲の最初の行の改行コード（無ければ文書の既定の改行コード）にします。範囲の最後の行が変えた行か足した行なら、元の最後の行の改行コードにします。文書の最後に改行が無ければ、無いままにします
- 書き戻した文書を読み直して、表の場所・前後の解釈と、もう一度書き戻しても同じ行になること（1 回で収束すること）を確かめます。HTML の表は、行数・列数と、各セルの位置・結合・見出し・配置も、ブックの内容と比べます
- 書き戻せない表や読み直しの問題があれば、`--force` を付けても文書全体を書き戻しません
- 「更新」に付ける要約（変えたセル・足した行と列・消した行と列の数）は、書き戻す行とは別に数えます。列の数が違うときは、入っている文字が多く重なる列同士を仮に対応させ、その列の文字で行を突き合わせ、対応した行の文字で列を突き合わせ直します。行と列を同時に足しても、元のセルは「変更」に数えません。対応したセルの文字・配置・見出し・結合を比べ、結合は左上で数え、同じセルの複数の変更もセル数では 1 個です

## 字下げされた表

- 表がどのコンテナ（リスト項目・説明・引用・脚注など）の中かは、comrak と同じ「本文の開始列」で決めます
- 接頭辞は行ごとに持ちます。変えない行は元の接頭辞、新しい行は続きの行の接頭辞、空行は続きの行の接頭辞から右の空白を除いたもの（引用の中なら `>`）にします。表の最初の行は、`- | a |` や `1. <table>` のように記号を含む元の接頭辞のままです
- 詰めたリストの中で表を HTML の表にすると、Markdown の部分の空行で項目の間隔が広がるので、警告を出します

## 制限

- Excel 実機（Windows の Excel 2021）では、開く・入力・行の挿入・シート名の変更・結合の解除・保存・`edit` を COM で確かめました。キー入力に固有の動き（オートコレクトなど）と、Excel for the web・Excel for Mac・LibreOffice は未検証です（検証記録）
- セルの一部だけの書式や色は書き戻しません
- セル全体の太字・斜体・取り消し線・下線、ハイパーリンク、コメント（メモ）は自動変換せず、文字だけを書き戻します。取り込みでは、表ごと・種類ごとに警告を出し、番地は 5 個までと残りの個数を示します
- 太字と塗りつぶしの組は見出しの書式として扱い、パイプ表の 1 行目の太字や、文字にリンク先が含まれるハイパーリンクには警告しません。ハイパーリンクに付く下線も警告しません
- Excel が数値・真偽値・数式・エラー値に変えたセルは、警告して文字を書き戻します。数値の書式が標準・文字列以外のセルと日付・時刻のセルは、`--force` が無ければ書き戻しを止めます
- `import`・`edit` に `--strict-text` を付けると、書式が標準・文字列でも数値・真偽値・数式・エラー値のセルがあるときは文書全体の書き戻しを止めます。`--strict-text` と `--force` は同時に指定できません
- HTML の表で、中身も変えたセルの属性（`align` 以外）は、表を作り直したときに引き継げません（警告を出します）
- 文字の `_x000D_` はセルに書けません（Excel が改行に変えるため）
