# 設計と変換の規則

[README](../../README.md) / [検証記録](../verification/readme.md)

## 全体の流れ

1. 文書を comrak と同じ規則で読み、パイプ表と HTML の表を見つける（`mdtable/blocks.py`・`document.py`）
2. 表ごとに格子のモデル（セルの位置・結合・見出し・配置・Excel に書く Markdown）を作り、ブックに書く（`workbook.py`）
3. 取り込みでは、ブックのモデルを元の表のモデルと比べ、違う表だけを書き戻す（`sync.py`）
4. 書き戻した文書を読み直し、表の場所・前後の解釈・もう一度書き戻したときの結果が変わらないことを確かめてから書く

## comrak に合わせた理由

GitLab は Markdown を comrak で解析します。表の検出や「HTML ブロックの中のどこが Markdown か」を自前で決めると、GitLab と違う所を表として読んだり、書き戻した表が GitLab で崩れたりします。そこで comrak の `src/parser/mod.rs`・`table.rs`・`scanners.re` の規則をそのまま Python に移しました。手元の文書 217 本で、葉のブロックの種類・行・祖先と表の行が comrak の構文木と一致することを確かめています（[検証記録](../verification/readme.md)）。

comrak の主な規則:

- 表は段落の最後の行と区切り行で始まる（段落を中断できる）。`---` だけの行は setext の見出しが先。同じ段落で一度失敗したら、その段落ではもう表にしない
- 表の行は、空行・コンテナの終わり・別のブロックの始まりまで続く。`|` の無い行も行になる。遅延行では続かない
- セルの区切りの `|` は、直前に `\` が 1 つでもあれば区切りにならない（`\\|` も区切らない）。セルの中身からは、奇数個の `\` の直後の `|` について `\` を 1 つ除く。書き戻しでは、`|` の前の `\` が偶数個（0 を含む）なら 1 つ足す。コードスパンの中の奇数個の `\` + `|` はパイプ表では書けないので、HTML の表にする
- 説明リストの説明の中身は、`:` の位置 + `:` と後ろの空白の幅（comrak の `marker_offset + padding`）の列から始まる

## ブックの形

- 「目次」シート、表ごとのシート（表は A1 から）、隠しシート `_mdtable`（veryHidden）
- セルは文字列の書式（`@`）で、値は代入した後に `data_type = "s"` にする。`=` で始まる文字や `#N/A` を数式・エラー値にしないため
- 列のスタイルにも `@` を付け、表の右にも数列分を足す。後から入力したセルも文字列になる。列のセルの配置がそろっていれば、列のスタイルにもその配置を付ける（表の下の行に入力したセルも同じ配置になり、パイプ表の列の配置と混ざらない）
- 結合で隠れるセルにも、左上のセルと同じ書式を付ける。結合を解いて入力しても文字列のまま（openpyxl は結合すると隠れるセルの書式を捨てるので、結合してから書式を付ける）
- 表全体の範囲に名前の定義 `mdtable_番号` を付ける。シート名を変えると Excel が参照を直すので、どのシートがどの表かを追える。目次のリンクもこの名前を指す
- `_mdtable` には、Markdown の絶対パスと相対パス、表ごとの種類・行範囲・元の表の本文の sha256・書き出した内容の指紋を書く
- `_xHHHH_` の形の文字は `_x005F_xHHHH_` にして書く（Excel が文字に戻してしまうため）。読むときは逆にし、`_x000D_` + 改行は改行にする
- 結合を含む行は Excel が高さを自動で合わせないので、内容から見積もる
- フォントは、書き出す PC に HackGen Console NF（日本語の等幅で、`\` が `¥` に見えない）が入っていればそれ、無ければどの Windows にもある BIZ UDゴシック。Windows はフォントの登録（`HKLM` と `HKCU` の `SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`）、ほかの OS は `fc-list` で調べる。環境変数 `MDTABLE_FONT` があれば、それを使う

## セルの文字（Excel 側の Markdown）

- セル内の改行は表示上の改行（GitLab では `<br>`）、空行は段落の区切りとして扱う。Excel で Alt+Enter した改行がそのまま改行に見えるようにするため
- それ以外は GLFM の Markdown のまま（リスト・説明リスト・コードブロック・強調・リンク・直書きの HTML）

### パイプ表のセル

- Excel へ: `<br>`（`<br/>`・`<BR >` も）を改行に、`<ul>`・`<ol start>`・`<dl>` の決まった形をリストと説明リストにする。それ以外のタグや文字はそのまま。行頭がブロックの記法になる文字（空白が続く `-`・`1.`・`:`、`>`・`#` など）はエスケープする（パイプ表のセルの中では文字として表示されているため）
- Markdown へ: 段落の中の改行は `<br>`、段落の区切りは `<br><br>`、リストは `<ul><li>`、説明リストは `<dl>`。インラインの Markdown はそのまま。行頭のエスケープはパイプ表の中では要らないので外す
- コードブロック・タスク・見出し・引用・字下げのコード・結合はパイプ表では書けないので、その表を HTML の表にする。表の次の行が同じコンテナの空でない行なら、`</table>` の後に空行を足す（HTML ブロックが次の行まで続かないように）

### HTML の表のセル

- GitLab の文書は、セルにリストやタスクを書くときは `<td>` の中に空行で区切った Markdown を書くよう勧めています。HTML ブロックの中では、同じ行の `**` などは処理されず、空行で区切った行だけが Markdown になるためです。そこで、書式のあるセルは `<td>`・空行・Markdown・空行・`</td>` で書き戻します
- 書式の無いセル（Markdown の記号もブロックの記法も無い）は `<td>文字</td>` の 1 行にし、改行は `<br>` にします
- Markdown の部分では、段落の中で次の行に続く行の末尾に `<br>` を足します（Markdown では改行が空白になるため）。読むときは逆に、`<br>` などの改行マークの付いた改行を改行に、マークの無い改行を空白にします
- リストとフェンスの前に空行を入れ、markdownlint の自動修正（MD031・MD032）が入らない形にします
- 閉じていないフェンスは閉じて警告します。閉じていない `<pre>` やコメント、コードの外の `<td>` などの表の構造のタグがあれば、書き戻さずに止めます
- `- [注]` のような 1 文字のタスク（GitLab は任意の 1 文字をタスクにする）は、`- \[注]` で書き戻します。`- [ ]`・`- [x]` はタスクのまま

### HTML から Excel へ

- `<p>` は段落、`<br>` は改行、`<ul>`・`<ol start>`・`<li>` はリスト（入れ子は親の文字の位置まで字下げ、隣り合う同じ種類のリストは記号を変える）、`<input type="checkbox">` はタスク、`<dl>` は説明リスト、`<pre>` はフェンス（`class="language-x"` や `lang` を言語名に）、`<code>` はコードスパン、`<strong>`・`<em>`・`<del>` は `**`・`*`・`~~`、`<a>` はリンク、`<img>` は画像、`<blockquote>` は引用、`<h1>` などは見出し
- `**` などが CommonMark の規則で強調として成り立たない位置（「」などの約物に接して閉じる、隣が `*` など）では、`<strong>…</strong>` のまま残します
- 属性付きの `<a>` や、知らない要素（`<kbd>`・入れ子の `<table>` など）は HTML のまま残します
- HTML の文字は空白をまとめ、実体参照を戻してから、Markdown で意味を持つ文字だけをエスケープします（`` ` ``・`*`・`[`・境界の `_`・組になる `~` と `$`・`<` + 英字・実体参照に見える `&`、行頭の記法）。`#123` や `@user` などの GitLab の参照の記号はエスケープしません

## 変えていないものを変えない仕組み

- 取り込みでは、元の表の本文（コンテナの接頭辞を除いた行）の sha256 で、今の文書の表を探します（同じ表が複数あれば順番で）。表の外を編集しても衝突になりません
- シートの内容が書き出したときと同じなら、その表は変更なしです
- 今の文書に元の表が見つからないときは、シートの内容を同じ番号の表に書き戻した結果が今の行と同じなら「適用済み」、違えば衝突です。モデルではなく書き戻した結果で比べるのは、書き戻すときに列の配置を多いほうにそろえたり、セルの文字を収束する形（`- a⏎b` → `- a⏎  b`）に直したりするためです
- パイプ表: 変わっていない行は元の行のまま、変わった行でも変わっていないセルは元のセルの文字のまま書きます（行の対応は difflib）
- HTML の表: 格子の形（各セルの位置と結合範囲）が同じなら、元の文字の上で、変えたセルの中身と、見出し・配置を変えたセルのタグだけを書き換えます。形が変わったら表を作り直しますが、変わっていない行は元の行の文字、変わっていないセルは元の中身のままです
- 書き戻した文書を読み直して、表がもう一度書き出し・書き戻ししても同じ行になること（1 回で収束すること）を確かめてから書きます

## 字下げされた表

- 表がどのコンテナ（リスト項目・説明・引用・脚注など）の中かは、comrak と同じ「本文の開始列」で決めます
- 接頭辞は行ごとに持ちます。変えない行は元の接頭辞、新しい行は続きの行の接頭辞、空行は続きの行の接頭辞から右の空白を除いたもの（引用の中なら `>`）にします。表の最初の行は、`- | a |` や `1. <table>` のように記号を含む元の接頭辞のままです
- 詰めたリストの中で表を HTML の表にすると、Markdown の部分の空行で項目の間隔が広がるので、警告を出します

## 制限

- Excel 実機（この形式のブックを Excel で開いて保存したときの挙動）は未検証です（[検証記録](../verification/readme.md)の確認の手順）
- セルの一部だけの書式や色は書き戻しません
- HTML の表で、中身も変えたセルの属性（`align` 以外）は、表を作り直したときに引き継げません（警告を出します）
- 文字の `_x000D_` はセルに書けません（Excel が改行に変えるため）
